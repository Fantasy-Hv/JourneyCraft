# 开发规范

## 一、分支管理

### 1.1 分支定义

整个项目主分支分为 `front-dev` 前端主分支和 `back-dev` 后端主分支，不要随意 push。

项目完成后将dev分支合并到stable分支并发布release。

### 1.2 基于分支的开发流程

1. 从主分支创建个人开发分支
   
   命名格式：`<前后端>-<个人名称>-<feature/bugfix>`
   
   示例：
   
   - `front-zhangsan-feature-diary`
   - `back-lisi-bugfix-login`

2. 在个人分支上开发功能

3. 代码审查及本地测试

4. 提交，发布分支

5. 经第二人再次测试通过后合并到主分支

### 1.3 提交规范

#### Commit Message 格式

```
<修改类型>（：<业务模块>）: <正文>
```

#### 提交示例

```bash
# 新功能
git commit -m "feat：diary: 添加日记自动生成功能"

# Bug 修复
git commit -m "fix：nav: 修复多目标路径规划计算错误"

# 重构
git commit -m "refactor：user: 重构用户认证逻辑，使用 JWT 工具类"

# 文档
git commit -m "docs: 添加xxx流程图"
```

#### Service 规范

```java
@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {

    private final UserMapper userMapper;
    private final UserPreferenceMapper preferenceMapper;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public UserVO getUserById(Long userId) {
        User user = userMapper.selectById(userId);
        if (user == null) {
            throw new BusinessException("用户不存在");
        }
        return convertToVO(user);
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public UserVO updateUser(Long userId, UserUpdateRequest request) {
        User user = new User();
        user.setId(userId);
        BeanUtils.copyProperties(request, user);
        userMapper.updateById(user);
        return getUserById(userId);
    }

    private UserVO convertToVO(User user) {
        UserVO vo = new UserVO();
        BeanUtils.copyProperties(user, vo);
        return vo;
    }
}
```

#### 异常处理规范

```java
// 自定义业务异常
public class BusinessException extends RuntimeException {
    private final Integer code;

    public BusinessException(String message) {
        super(message);
        this.code = 500;
    }

    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
    }
}

// 全局异常处理器
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        return Result.error(e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getAllErrors().stream()
            .map(DefaultMessageSourceResolvable::getDefaultMessage)
            .collect(Collectors.joining(", "));
        return Result.error("参数验证失败：" + message);
    }
}
```

## 五、数据库规范

### 5.1 表命名

- 表名：`t_模块_实体` 格式，如 `t_user_info`, `t_scenic_area`
- 使用小写字母和下划线
- 使用复数形式表示关联表，如 `t_group_members`

### 5.2 字段命名

- 使用小写字母和下划线
- 主键统一使用 `id`
- 外键使用 `关联表名_id` 格式
- 时间字段使用 `xxx_at` 结尾，如 `created_at`, `updated_at`
- 布尔字段使用 `is_` 开头，如 `is_deleted`, `is_active`

### 5.3 必备字段

每张表必须包含以下字段：

```sql
id              BIGINT PRIMARY KEY AUTO_INCREMENT,
created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
is_deleted      TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除 0:否 1:是'
```
